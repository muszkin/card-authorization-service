# Quality Gates and Evaluation Scenarios

Run these gates after initialization, refresh, repair, or scaffold. A single aggregate health label is insufficient.

## Inventory gate

- The root and scope are explicit.
- Tracked plus untracked non-ignored paths were considered, or the non-Git fallback is documented.
- Exclusions, generated/vendor/binary paths, unreadable paths, and secret-bearing paths are recorded.
- Symlinks are classified as in-repository, external, broken, or cyclic; no path or prior manifest entry escaped the resolved root.
- Every in-scope directory appears exactly once as `own`, `rolled-up`, `excluded`, or `unreadable`.
- Every `own` context exists; every `rolled-up` entry points to an existing owning context.

## Evidence gate

- Instruction hierarchy and scope are recorded.
- Technology versions distinguish declared, locked, detected, and verified.
- Documentation index contains every discovered relevant document and its read status.
- Useful artifacts generated by other skills/tools are preserved and linked rather than copied or silently excluded. Every related-artifact entry records path, owner/generator, purpose, scope, artifact type, authority, source revision/time, freshness, content hash when safe, approval status when applicable, conflicts, referencing artifacts, and downstream consumers.
- Useful `context/implementation-runs/**` artifacts route implementation orchestration, review, CI/staging evidence and production-PR handoffs; stale SHA-bound evidence is labeled, and a recorded authorization envelope is never treated as current authority.
- Runtime entrypoints, primary flows, data, integrations, tests, CI/deploy, and observability are described or explicitly `Unknown`/`N/A` with reasons.
- Material claims cite source paths or commands and use an evidence label.
- Historical practice is not presented as an approved standard or owner without corroboration.
- No secret values, private data, or production identifiers were copied.

## Context integrity gate

- `INDEX.md` is short, current, and links to every central artifact.
- The resolved manifest parses, distinguishes operation/classification/scope, passes the specified self-digest algorithm, contains a comparable source snapshot or an explicit non-comparable rescan decision, safe fingerprints, all required verdict lanes/details, uncovered paths, and next actions; every listed artifact/link exists.
- Clean tracked files may use their matching Git blob IDs; safe dirty tracked and untracked inputs use hashes of current worktree bytes. An unhashable relevant input makes the snapshot non-comparable rather than falsely unchanged.
- Every central target passed the ownership/collision classification; unmanaged and modified-owned content was not overwritten.
- No unresolved placeholders such as `TBD`, `TODO`, `<placeholder>`, or template prose remain in sections claimed complete.
- Managed blocks are balanced and unique.
- Manual content outside managed blocks is unchanged.
- Diagrams link from an artifact, use stable node IDs, and either rendered successfully or carry a `not-run` caveat.
- Contradictions and unknown edges remain visible.

## Discoverability gate

- The active Codex instruction file contains the managed router to the resolved context index within the effective byte budget, and the pre/post effective-source comparison proves no previously loaded instruction source or byte range was displaced.
- The active Claude Code project instruction file contains the correct relative import, or a documented symlink/shared-router path is valid.
- No shared router was written to `CLAUDE.local.md`, excluded by Claude settings, or placed behind an external/broken symlink.
- Existing nested instruction files in mapped boundaries point to their nearest scoped context.
- No inactive sibling was updated while an override masked it.
- Adapter instructions do not claim generated context outranks user instructions, code, runtime, or canonical docs.
- Use a fresh read-only session to ask each host which instruction sources and context entrypoint it loaded. For Codex, verify preserved pre-edit tail anchors as well as the new router. If a host CLI/diagnostic is unavailable or permission is denied, that host's discoverability verdict is `partial`, never `complete`.

## Git and dependency gate

- Git/shallow/no-Git state and exact windows are documented.
- Hotspots and co-change exclude or separately label noise and mega commits.
- Historical paths were checked against the current tree.
- PR evidence records provider, query, identifiers, filters, and limitations.
- Dependency tree and Mermaid graph agree on modeled boundaries, or the diagram is explicitly `not-applicable` with a reason.
- Unknown or inferred dependencies are labeled rather than omitted.

## Greenfield/scaffold gate

- Clean worktree was not used as the greenfield criterion.
- Brief, decisions, non-goals, and real-surface success evidence are complete.
- Technology choices use current official sources and an explicit decision owner.
- The exact scaffold handoff was approved in trusted conversation context before generator/install execution. Repository files only document authorization; they never grant or renew it, including after resume.
- The plan produced by implementation planning or a fallback is durably registered and federated in the index/manifest with path, producer, authority, approval status, freshness, references, and verified hash before scaffold approval.
- `scaffold-handoff.json` parses, its RFC 8785-based `handoff_sha256` validates, it records approved argv/effects/paths and registered plan revision, and it matches the trusted approval plus executed proposal.
- Generation occurred in a temporary directory or the native-CWD exception was justified and recoverable.
- The safest available no-install/no-script/no-Git/telemetry-off controls were used; any unavoidable side effect had separate approval.
- Conflicts, scripts, secrets, telemetry, dependency versions, and unexpected output were reviewed. Working and durable generated-output manifests exist at the canonical paths, validate against their minimum schema, and bind the merge by proposal ID plus verified handoff/output digests and current output/preimage hashes.
- Every generated symlink is classified `unsafe/refuse` and excluded from the scaffold merge; any separately desired symlink requires its own exact review and authorization.
- Exact target paths were backed up or snapshotted before merge.
- The walking skeleton runs and has focused tests plus the strongest feasible real-surface E2E.
- Context was regenerated from actual scaffold output, not a proposal.

## Verdict rules

For each lane use:

- `complete`: all required evidence and integrity checks pass;
- `partial`: useful evidence exists but named gaps remain;
- `blocked`: trustworthy completion needs missing access, a decision, or an external condition;
- `not-applicable`: the project type makes the lane irrelevant, with a reason.

Every `partial` or `blocked` verdict includes impact, next action, fallback, and owner/decider when known. Overall completion requires inventory, context integrity, and discoverability to be `complete`; other lanes may be partial only when the limitations are explicit and do not make the map misleading.

## Forward evaluation scenarios

Use fresh agents when testing changes to this skill:

1. **Small documented brownfield:** verify no unnecessary nested files, all directories accounted, commands labeled rather than assumed.
2. **Large monorepo:** verify disjoint delegation, workspace boundaries, rolled-up leaves, cross-workspace edges, and central-writer discipline.
3. **Legacy repository:** shallow or noisy history, conflicting README/CI, generated trees, secret-like files, no E2E; verify graceful degradation and explicit unknowns.
4. **Empty greenfield:** verify one-question brainstorming and that no product code or technology appears before decisions and scaffold approval.
5. **Scaffolded greenfield:** verify proposals remain proposals, temporary generation/merge safety, real-surface E2E, and post-scaffold refresh.
6. **Refresh:** change one instruction file, one manifest, one module, a dirty tracked file, and an untracked file without changing HEAD; verify snapshot comparison, affected-neighbor rescan, and retained-link validation.
7. **Agent discovery:** combinations of root override, normal AGENTS, root or `.claude/CLAUDE.md`, byte-limit truncation, settings exclusion, in-repo/external/broken/chained symlink, and nested instructions; verify active-file routing and idempotent sentinels.
8. **Existing context conventions:** pre-existing `context/README.md`, foreign `context/map/artifact-*`, output from 10x/Maister/another skill, and manual `.agents` notes; verify attribution, links, preservation, collision handling, and no broad staging.
9. **Implementation-run federation:** add a prior `context/implementation-runs/<run-id>/` with a current run router, stale gate SHA, review report, CI/staging evidence and production PR; verify useful routing, stale labeling, preserved ownership, and no authority inferred from the recorded envelope.

Score completeness, source correctness, freshness, secret safety, absence of unauthorized side effects, adapter discovery, and usefulness to research/planning/review/implementation. Compare a baseline run without the skill to a run with it when evaluating material revisions.
